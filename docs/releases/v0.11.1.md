# v0.11.1 · 修复：GUI 启动找不到 mocli

发布日期：2026-09-15 · 修复版 · 需求/验收 `docs/PRD-v0.11.1.md`

## 修复

### 从 Dock/Finder 启动时 mocli 误报「未检测到」

- **现象**：v0.11.0 发布当天另一台机器实录——mocli 已安装、终端 `which` 找得到，wx-kit 从
  Dock 启动后订阅页「墨问作者」tab 与设置页恒报「未检测到 mocli」，墨问功能整个不可用。
- **根因**：macOS 从 Dock/Finder 启动的 GUI 应用不加载 `~/.zshrc`，进程只拿系统最小 PATH
  （`/usr/bin:/bin:/usr/sbin:/sbin`）——nvm/homebrew 装的 mocli 不在其中。原检测仅靠
  `which`，GUI 场景必然落空；开发模式从终端启动继承完整 PATH，故测试期无法暴露。
- **修复**：mocli 定位升级为三级探测链——`which` → 常见安装位（homebrew/volta/asdf/
  npm-global + nvm 最新 node 版本目录，纯文件系统检查）→ login shell 兜底
  （`$SHELL -ilc 'command -v mocli'`，超时 3 秒）。检出后将 mocli 所在目录注入进程 PATH
  （先于版本探测），同时解决 `mocli` 与其 shebang `#!/usr/bin/env node` 依赖的 `node`
  两个可达性。GUI 与 CLI 双入口统一走该链；Windows 不受此问题影响（GUI 进程继承注册表
  PATH），行为不变。

## 验证

- 676 项单测（含 13 条新增，含「注入先于版本探测」时序钉子）、lint、TypeScript 检查、
  GUI e2e 全绿。
- 打包产物在模拟 launchd 最小 PATH 环境真机验证：CLI `mowen detect` 返回 installed + 版本 +
  认证身份；GUI 启动 10 秒内将 mocli 绝对路径与版本写入设置；login shell 兜底通道独立验证可用。
- 正常终端环境行为不变（`which` 一步命中，零额外探测开销）。

## 升级建议

v0.11.0 用户若使用墨问功能（mocli 装在 nvm/homebrew 等非系统路径），建议升级；仅使用微信
功能的用户无感知变化。

其余能力与 v0.11.0 一致，见 `docs/releases/v0.11.0.md`。
